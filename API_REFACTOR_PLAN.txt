API REFACTOR PLAN — Redukcja zbędnych endpointów
=================================================

PROBLEM
-------
Prawie każdy endpoint w routes.py to cienki wrapper na run_script():
  result = run_script("controller", "metoda", payload)
  return result.get("result") or fallback

Taki sam efekt daje istniejący uniwersalny endpoint:
  POST /scripts/run  { script: "...", method: "...", payload: {...} }

17 z 30 endpointów nie wnosi żadnej logiki biznesowej — to duplikaty /scripts/run.


ENDPOINTY DO ZACHOWANIA (mają realną wartość)
---------------------------------------------
1. POST /scripts/run          — core dispatcher
2. POST /scripts/async         — Celery async path
3. GET  /jobs/{job_id}         — sprawdzanie statusu zadań Celery
4. POST /tunnel/key            — file upload (UploadFile), nie da się przez /scripts/run
5. GET  /tunnel/logs           — czyta plik bezpośrednio, nie przez script_runner
6. POST /devices/add-and-sync  — orkiestruje: add → find → sync (3 wywołania run_script)
7. POST /devices/add-batch-and-sync — orkiestracja w pętli + deduplikacja
8. GET  /devices/command       — pre-fetch urządzenia + run_script (2 kroki)
9. POST /consoles/sessions     — przechodzi specjalną ścieżkę _run_consoles_controller (asyncio)
10. POST /consoles/sessions/command — j.w.
11. POST /consoles/sessions/close   — j.w.
12. POST /consoles/execute          — j.w.

PLAN MIGRACJI (frontend)
------------------------
1. W DataService.ts zastąpić dedykowane wywołania requestJson('/api/devices', ...)
   na runScript('settings-devices_controller', 'get_all_devices', {})
   — metoda runScript() już istnieje i wywołuje POST /scripts/run.

2. Analogicznie dla accounts, sites, tunnel, modules, connections, system/cleanup.

3. Usunąć wrappery z routes.py.

4. GET /connections wymaga dodatkowej pracy — teraz czyta plik bezpośrednio,
   trzeba dodać metodę w devices_controller (np. get_all_connections) albo
   stworzyć connections_controller.


UWAGI
-----
- Nie usuwać od razu — najpierw zmigrować frontend, potem wyciąć endpointy.
- Terminal endpoints (4 szt.) — do osobnej decyzji (usunąć całkowicie lub zostawić).
- Po migracji routes.py skurczy się z ~480 do ~150 linii.
